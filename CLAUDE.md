## Що це за проєкт

WordPress-плагін — плаваючий віджет соцмереж/месенджерів (карусель іконок + бульбашка привітання)
з адмін-панеллю для керування месенджерами (drag-and-drop), статистикою кліків/переглядів та
мультимовним інтерфейсом. Розроблений як безкоштовна власна альтернатива платному SendPulse-віджету
для клієнтської бази **ObriiFlow Studio** (~270 сайтів на WordPress).

- **Локальна назва папки/репо:** `social-connect-widget`
- **Опублікований slug на WordPress.org:** `obriiflow-social-widget`
  → https://wordpress.org/plugins/obriiflow-social-widget/
- **Попередня версія (інший бренд, можливо застаріла):** `sw-messenger-widget`
  → https://github.com/PsiBotCOM/sw-messenger-widget (не факт, що підтримується — уточнити з Андрієм,
    чи це той самий проєкт, перейменований, чи окрема гілка розвитку)

## Naming conventions — КРИТИЧНО, не порушувати

Плагін пройшов ревʼю WordPress.org і всі ідентифікатори вже приведені до єдиного префіксу.
**Не вигадуй нових префіксів і не повертай старий `sw_`.**

| Що | Значення |
|---|---|
| Function/hook/option prefix | `obrisowi_` (OBRiiflow SOcial WIdget) |
| DB table | `obrisowi_stats` (створюється/дропається через `uninstall.php`) |
| Frontend JS object (`wp_localize_script`) | `OBRISOWI_CONFIG` |
| Admin JS object | `OBRISOWI_MESSENGERS` |
| CSS-класи (лишились без змін, НЕ перейменовувати) | `.sw-widget`, `.sw-list` |
| Admin assets | `admin/admin.css`, `admin/messengers.js` (окремо від фронтенду) |

## Безпека — обовʼязкові патерни (вимоги ревʼю WP.org)

Плагін уже пройшов повний security-аудит під час публікації. Будь-який новий код повинен
дотримуватись тих самих правил:

- Усі SQL-запити — тільки через `$wpdb->prepare()`, ніколи конкатенація рядків.
- Будь-який echo user-facing даних — обов'язково `esc_html()` / `esc_attr()` / `wp_kses()`,
  причому **екранування має відбуватись безпосередньо в місці виводу** (echo), а не раніше —
  WP.org review team на цьому наполягає навіть якщо змінна вже "чиста".
- Дані з `$_POST` / `$_GET` — через `wp_unslash()` перед обробкою.
- Inline `<script>`/`<style>` в PHP-файлах не допускаються — усе через
  `wp_enqueue_script/style` або `admin_enqueue_scripts`.

## Messenger deep links — перевірені робочі формати

Ці формати виведені емпірично (методом проб і дебагу на живому сайті), не міняти без причини:

- **Telegram:** `tg://resolve?domain=USERNAME` — **без** `target="_blank"` на `<a>`.
- **Viber:** `viber://add?number=380XXXXXXXXX` — дія `add`, номер **без** `+` на початку.
  Формат `viber://chat?number=%2B...` ненадійний, не використовувати.
- **Instagram (DM):** `https://ig.me/m/username` — універсальний формат, працює і на мобільних, і на десктопі.
- **YouTube:** прямих DM не існує в принципі, не намагатись імітувати.

⚠️ **Головна пастка:** `target="_blank"` на анкорах ламає deep links (`tg://`, `viber://`) і на
десктопі, і на мобільних. Якщо месенджер "не відкривається" — перше, що перевіряти.

Референсний клієнтський деплой з підтвердженими лінками: `aero-decor.com`
(Telegram + Instagram підтверджено робочими, Viber — фінальний тест ще потрібен).

## Структура репозиторію / білд

- Код плагіна лежить у підпапці `plugin/` (не в корені репо).
- `build.sh` та `*.zip` — в `.gitignore`, у git не комітяться.
- ZIP для WordPress.org SVN збирається строго через:
  ```bash
  git archive --prefix=<slug>/ HEAD:plugin > <slug>.zip
  ```
  Назва папки всередині ZIP **повинна** збігатись зі slug плагіна — інакше WP.org release.
- `.DS_Store` вже потрапляли в git раніше — якщо зустрінеш, патерн `**/.DS_Store` у `.gitignore`
  прибирає їх ретроактивно (`git rm -r --cached` + commit).

## Публікація на WordPress.org

- Керується через SVN (SmartSVN на Mac), не напряму git.
- Робочий флоу для нової версії: **Tag+Branch → Add Tag** у SmartSVN.
- WordPress.org **блокує автоматичні HTTP-запити (403)** — перевірку зайнятості slug чи
  публікацію нової версії не можна скриптувати curl'ом, лише через браузер вручну
  (404 на `/plugins/<slug>/` = slug вільний).
